🎯 HOY VAS A LOGRAR…

Diseñar tu Space Invaders en papel antes que en código (qué objetos existen y qué datos guarda cada uno) y construir el esqueleto del juego: el canvas espacial, el game loop y tu nave moviéndose con ← → sin escaparse de la pantalla. 🚀

🧠 EL CONCEPTO: PRIMERO SE PIENSA, LUEGO SE TECLEA

Los estudios de videojuegos no abren el editor y empiezan a teclear como locos. Primero responden una pregunta: ¿quiénes viven en este juego y qué necesita saber cada uno? A eso se le llama diseño, y es el superpoder que separa a quien copia código de quien CREA juegos.

Diseñar un juego es como planear una obra de teatro escolar 🎭: antes del estreno haces la lista de personajes y qué necesita cada uno (vestuario, posición en el escenario, diálogos). En tu juego, los personajes son objetos y sus necesidades son datos: x, y, ancho, alto, velocidad…

Cada actor es un objeto como los del Nivel 7: una ficha con datos. La nave es UNA, pero balas e invasores serán arreglos de objetos.

✏️ TU TURNO

Te toca: en esta versión la nave solo sabe ir a la izquierda y además se escapa de la pantalla. Completa moverNave(): agrega el movimiento a la derecha y las dos paredes invisibles. (Recuerda: 🖱️ clic en la vista previa antes de usar el teclado.)

@@CODE:n9l1-turno@@
PISTA 1 El movimiento a la derecha es el ESPEJO del de la izquierda: mismo if, pero preguntando por teclas["ArrowRight"] y sumando la velocidad en vez de restarla.
PISTA 2 Pared izquierda: if (nave.x < 0) nave.x = 0; — ¿y la derecha? El borde no es canvas.width: es canvas.width - nave.ancho, porque la x de la nave es su esquina IZQUIERDA y la nave mide 60 de ancho.
SOLUCIÓN EXPLICADA 
function moverNave() {
  if (teclas["ArrowLeft"]) {
    nave.x = nave.x - nave.velocidad;   // ← resta: hacia la izquierda
  }
  if (teclas["ArrowRight"]) {
    nave.x = nave.x + nave.velocidad;   // → suma: hacia la derecha
  }
  // Pared izquierda: si se pasó de 0, la regresamos a 0
  if (nave.x < 0) nave.x = 0;
  // Pared derecha: su esquina izquierda no puede pasar de
  // canvas.width - nave.ancho (si no, se saldría media nave)
  if (nave.x > canvas.width - nave.ancho) {
    nave.x = canvas.width - nave.ancho;
  }
}
Este patrón (mover y luego "recortar" contra los bordes) lo vas a usar en TODOS tus juegos futuros. Guárdalo en tu cerebro para siempre. 🧠

❓ MINI-QUIZ

1. ¿Por qué conviene diseñar los objetos ANTES de programar?

El diseño es el plano del arquitecto 📐: puedes construir sin él, pero el resultado se cae. Con la tabla de diseño, cada lección de este nivel ya sabe exactamente qué construir.

2. La nave está en nave.x = 430, mide 60 de ancho y el canvas mide 480. ¿Qué pasa?

x es la esquina IZQUIERDA del rectángulo. Por eso la pared derecha se calcula como canvas.width - nave.ancho = 480 − 60 = 420.

3. ¿Qué hace el objeto teclas en nuestro juego?

Con keydown apuntamos true y con keyup apuntamos false. El game loop pregunta 60 veces por segundo "¿sigue presionada?" — así el movimiento es suave y continuo. 🎹
