Return: el platillo que te devuelve 🎁

🎯 HOY VAS A LOGRAR…

Crear funciones que te ENTREGAN un resultado con return, guardarlo en una variable y seguirlo usando. Y de paso vas a derrotar al ERROR #1 de todos los principiantes del planeta: confundir print con return. Hoy lo matas de frente. ⚔️

🧠 EL CONCEPTO

Tus funciones ya reciben ingredientes… pero hasta ahora solo GRITAN cosas a la pantalla con print. ¿Y si quieres que la función calcule algo y te lo dé para seguirlo usando? Sumarle, compararlo, guardarlo… Para eso print no sirve. Necesitas return.

print es cuando el cocinero te ENSEÑA el platillo por la ventanilla 🪟: lo ves… y ya, se queda en la cocina. No te lo puedes comer.
return es cuando te lo ENTREGA en la mano 🤲: ahora es tuyo — te lo comes, lo guardas en un táper (una variable 📦) o lo usas de ingrediente en OTRA receta.

Los ingredientes 2 y 3 entran, la máquina trabaja, y return ENTREGA el 5… que viaja directito a la caja resultado 📦. Eso print jamás podría hacerlo: solo lo habría enseñado por la ventanilla.

📝 Cómo se escribe (y se aprovecha)

def sumar(a, b):
    return a + b            # ENTREGA el resultado y termina

resultado = sumar(2, 3)     # el 5 entregado cae en la caja
print(resultado)            # 5
print(resultado * 10)       # 50 — ¡puedes seguirlo usando! 💪
  • return entrega el valor a quien llamó la función. La llamada sumar(2, 3) literalmente "se convierte" en 5.
  • return también termina la función ahí mismo: si hay líneas después del return, ya no corren. 🚪
  • OJO: return entrega en silencio: no imprime nada. Si quieres VER el valor, tú lo imprimes: print(sumar(2, 3)).

💀 EL ERROR CLÁSICO #1: guardar un print

Todos, TODOS los principiantes hacen esto alguna vez — hoy te toca verlo venir:

def sumar_mal(a, b):
    print(a + b)            # solo lo ENSEÑA por la ventanilla 🪟

resultado = sumar_mal(2, 3) # intentas guardar el "platillo"...
print(resultado)            # None 😱 ¡la caja quedó VACÍA!

None significa "nada". La función mostró el 5 en pantalla, sí… pero nunca lo entregó, así que en la caja resultado no cayó nada. Ver un platillo por la ventanilla no lo pone en tu táper. 🪟🙅 Cuando veas None donde esperabas un valor: a tu función le falta su return. Es EL diagnóstico clásico.

🔗 Combinar funciones: el resultado de una entra a otra

Aquí es donde return se pone épico: como la función entrega un valor, puedes usar ese valor como ingrediente de otra función:

def doble(numero):
    return numero * 2

print(doble(doble(5)))      # doble(5)→10, doble(10)→20 🤯
combo = sumar(doble(4), 1)  # doble(4)→8, sumar(8, 1)→9

Con print esto sería imposible: no puedes hacer doble(un-grito-en-la-pantalla). 😄

🏠 Variables locales: lo que pasa en la función, se queda en la función

Última regla del día: las variables que creas ADENTRO de una función son locales — son los trastes del cocinero 🍳: viven en su cocina y NO salen por la ventanilla. Afuera no existen:

def preparar_pocion():
    ingrediente_secreto = "pata de rana 🐸"   # nace ADENTRO...
    return "Poción lista ✨"

print(preparar_pocion())      # Poción lista ✨
print(ingrediente_secreto)    # 💥 NameError: no existe aquí afuera

¿Por qué Python es así de "envidioso"? ¡Es un favor! Cada función es su propia cocina cerrada: sus variables no chocan con las tuyas ni con las de otras funciones. Lo ÚNICO que sale de la cocina es lo que la función decide entregar con return. 🚪🎁

✏️ TU TURNO: LA CALCULADORA DE XP ⚡

En tu juego, cada enemigo derrotado da 25 XP. Crea la función calcular_xp(enemigos) que RETORNE (no imprima 👀) los puntos ganados, y úsala:

PISTA 1 La receta es cortita: def calcular_xp(enemigos): y adentro UNA línea que empieza con return. Nada de print adentro — esta función ENTREGA, no grita. 🤫
PISTA 2 Para el TODO 2, la llamada va del lado derecho del =: xp = calcular_xp(4) — la llamada "se convierte" en 100 y cae en la caja. Para el combo: cada llamada entrega su número, y los números entregados se suman como cualquier suma: 50 + 75.
SOLUCIÓN EXPLICADA 
def calcular_xp(enemigos):
    return enemigos * 25            # ENTREGA el cálculo 🎁

xp = calcular_xp(4)                 # la llamada se convierte en 100
print("Ganaste", xp, "XP")          # Ganaste 100 XP

print(calcular_xp(2) + calcular_xp(3))   # 50 + 75 = 125 ✅
El combo es la magia de return: cada llamada se convierte en su valor entregado, y esos valores se pueden sumar, comparar, guardar… Si tu función usara print, el combo daría el famoso error de sumar None. 💀

🚑 ¿ATORADO? ASÍ TE DESATORAS

  1. ¿Te salió None? Diagnóstico instantáneo: tu función hace print pero no return. Enseñó el platillo… y no lo entregó. 🪟
  2. ¿No se imprime nada de nada? Al revés: tu función SÍ retorna, pero recuerda que return entrega en silencio. Envuélvela en un print: print(calcular_xp(4)).
  3. ¿NameError al usar una variable afuera? Es local: nació adentro de la función y ahí se quedó. Lo que necesites afuera, sácalo con return.
  4. ¿Pusiste código después del return y no corre? Así es la regla: return entrega y CIERRA la función en ese instante. 🚪

❓ MINI-QUIZ

1. ¿Cuál es LA diferencia entre print y return?

La ventanilla 🪟 contra la entrega en mano 🤲. print es para que lo vea un humano; return es para que lo use el resto de tu programa. Los juegos calculan mil cosas con return y solo imprimen unas cuantas.

2. La función mostrar_suma(a, b) solo hace print(a + b). ¿Qué guarda resultado = mostrar_suma(2, 3)?

El error clásico #1 💀: sin return, la caja queda vacía (None = "nada"). Ver el platillo por la ventanilla no lo mete a tu táper. Cuando veas None: falta un return.

3. Una variable creada ADENTRO de una función, ¿se puede usar afuera?

Lo que pasa en la función se queda en la función 🍳. Cada función es una cocina cerrada, y su única puerta de salida es el return.
